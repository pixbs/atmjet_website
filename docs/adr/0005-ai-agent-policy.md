# ADR-0005: AI agents, attribution ban, identity and enforcement

Status: accepted (2026-09-11)

## Context

AI coding agents (Claude Code, Codex, Cursor, Copilot) work on this repository alongside people. Their tools add attribution by default (`Co-Authored-By` trailers, "generated with" footers, session links, `claude/`-style branch names) and forget repository conventions between sessions. The owner requires that no AI attribution ever appears in the repository and that conventions are enforced automatically.

## Decision

- **Ban.** No AI attribution in commits, pull request titles and bodies, comments, branch names or code: no co-author trailers naming AI tools or vendors, no tool-generation footers, no session links, no robot emoji, no vendor no-reply e-mail address as author or committer.
- **Identity.** Agent commits are authored as the repository owner identity configured in the environment. CI checks author and committer strings against the banned identity patterns; there is no allowlist, because it would need a repository variable and adds nothing a single-owner repository can act on.
- **One pattern file.** `scripts/ci/attribution-patterns.txt` feeds the CI scanner, the scrub step, the commit-msg sanitiser, commitlint and the Claude Code hook, so a new footer form is added in one place and covered by the self-test.
- **Enforcement layers, all required:**
  1. `AGENTS.md` (imported by `CLAUDE.md`, referenced by `.github/copilot-instructions.md`) states the rules on the first screen of every session.
  2. `.claude/settings.json` disables Claude Code attribution and denies force pushes, direct pushes to `master` and legacy-ref deletion; `.claude/hooks/block-attribution.sh` blocks offending commands before they run.
  3. Git hooks (lefthook): commitlint with the `no-ai-attribution` rule on every commit; branch-name check on push.
  4. The `conventions` workflow (required check): branch name, PR title, commit messages, attribution scan of commit messages, identities and PR text.
  5. Scrubbing where agents have no reach: the `conventions` workflow rewrites the pull request description without tool footers before scanning it, and the `scrub comments` workflow does the same for comments. Some agent platforms append a footer to every description or comment they write, even through the API; the scrub removes it within the same run, so no one has to edit by hand.
  6. The `branch guard` workflow deletes branches created with a tool prefix and tells any pull request opened from them why.
- **Branch prefixes generated by tools are rejected.** An agent whose environment created such a branch creates the correctly named branch from it and opens the pull request from that branch.
- **Scope of agent work:** one issue per pull request, small verified commits, tests with every change, never the legacy database.

## Consequences

- The convention checks are self-tested (`bun run check:conventions`) so they cannot rot silently.
- Copilot and Codex read `AGENTS.md` natively; Claude Code reads it through `CLAUDE.md`. Cursor users should point their rules at `AGENTS.md`.
